# Expeditions Macro v1.3.0-beta.54

This beta adds a verified, user-controlled application update flow, preserves recurring task progress across intentional stops, and fixes field-reported Bounty Board and Placement Setup edge cases. It is published as a silent prerelease and does not send a Discord release announcement.

## Highlights

- The app checks its matching official GitHub release channel at startup by default and presents a non-modal update notice. Users may disable checks in Settings.
- Downloading an update and opening its installer require separate explicit confirmations; the app never installs silently or forces a restart.
- Challenge rotation evidence and partial combined Gold Mine/Resource Drill completion survive stop/start and remain clearable through Reset progress.
- Bounty tasks always use zero parked non-viable Bounties; the obsolete control is removed and legacy saved values are normalized away.
- Legacy Expedition Placement Setups with duplicate unit slots can be repaired progressively instead of having every delete rejected.
- The field-observed bright Bounty Board Back control is accepted only with the independent owning-page structure.

## Safety boundaries

- Updates must match the official repository, current release channel, semantic tag, prerelease flag, exact four-asset inventory, trusted GitHub HTTPS hosts, declared sizes, GitHub digests, and `SHA256SUMS.txt` before an installer can be staged.
- The installer is rehashed immediately before launch; canceled, partial, tampered, or stale stages are removed, and no update input occurs without user consent.
- Recurring task state remains local to the plan and is stripped from shared plans.
- Placement edits may reduce existing legacy duplicate debt but cannot introduce or worsen a duplicate unit slot.
- Bounty Board input still requires fresh, stable ownership and independent live action evidence.
